# 计划：从校准版Markdown提取食人资料到CSV

## Context
用户希望从 `data/校准版/明清时期灾荒食人现象研究_陈岭_校准版.md` 文件中提取结构化数据，存储到CSV。源文件约6万字，包含明朝1368年-1644年、清朝1644年-1912年的灾荒食人记录。

## 数据结构分析

### 年份信息（从标题行提取）
```
### 明太祖洪武二十年（1387年）
```
- 年号年份：`洪武二十年`
- 公元年份：`1387`

### 行政区划（从数据行提取）
- 省级单独一行标记，如 `山东：`
- 后续条目继承前面的省份，如 `济南市：...`
- 也有同一行包含省县，如 `安徽：怀远县：...`

### 来源
- 格式：`——来源` 或 `——来源，第X页`

## 程序设计

### 技术方案：Python 脚本

### 核心逻辑

1. **维护上下文状态**
   - `current_province`：当前省份（初始为空）
   - `current_year`：当前年号和公元年份
   - 处理行时更新上下文
   - 示例：`山东：`出现后，`current_province = "山东"`，直到出现另一个省名（如`河南：`），`current_province`才更新

2. **正则表达式匹配年份标题**
   ```python
   # 匹配 ### 标题行，提取年号和公元年份
   pattern = r'^### (.+?)（(\d+)年）$'
   ```

3. **省级单独行检测**
   ```python
   # 匹配 省级标题行，如 "山东：" 或 "安徽省："
   province_pattern = r'^(.+?)：$'
   ```
   - 设置 `current_province`
   - 后续行继承此省份

4. **数据行解析**
   - 先判断冒号结构：
     - 两个冒号（`A：B：内容`）：A通常是省，B是市或县
     - 一个冒号（`A：内容`）：A可能是省标记、市或县
   - 判断市/县的方法：名称以"市""府"结尾的填"市"字段；以"县"结尾的填"县"字段
   - 以"州"结尾的（如泽州、解州）→ 填"古代地名"字段，同时转换为现代行政区划填入"市"字段
   - 判断A是否为省份：用省份列表匹配，不在列表中则A不是省份
   - 情况A：`省：市：内容。——来源` → 省、市填具体值，县填"无"
   - 情况B：`省：县：内容。——来源` → 省、县填具体值，市填"无"
   - 情况C：`市：县：详情。——来源` → 继承当前省份，市、县填具体值
   - 情况D：`县：详情。——来源` → 继承当前省，市填"无"，县填具体值
   - 情况E：`州：详情。——来源` → 省、市填现代对应值，古代地名填原州名
   - 情况F：`市等/县等：详情。——来源` → 去掉"等"，分别填入对应字段；如内容中还提到其他县名，则拆分成多条记录

5. **来源处理**
   - 仅保留书名，去除年号、卷次和篇名
   - 年号不属于书名，应去除：`康熙《续修陈州志》卷四灾异` → `《续修陈州志》`
   - 转引来源保留原始来源，如：`《和政县志》（民国十九年），转引自《西北灾荒史》第397页` → `《和政县志》`

6. **提取标准**
   - 包含以下任一关键词/模式的记录才提取：
     - "人相食"：标准表述
     - "相食"、"民相食"、"人相食"、"父子相食"、"兄弟相食"等
     - "至相食"、"多相食"、"或相食"：变异表述
     - "人有相食者"、"人有相食者"：存在型表述
     - "易子而食"：明确食人行为
     - "割人肉"、"杀人而食"、"食人肉"：明确描述食人动作
     - "相为割食"、"自食其子/父"：明确描述互相食人
     - "民至相食"：致饿而死导致的相食
   - **不提取**：仅描述饥荒但未提及食人行为的记录

7. **泛指记录处理**
   - 无明确县市但能确定省的记录：省填具体值，市县填"无"
   - 如：`山东并饥，...父子或相食` → 省：`山东`，市：`无`，县：`无`

8. **无明确地点开头的记录**
   - 优先检查来源是否包含地名（如"渭南县志"）
   - **不进行推断**，在备注中标注"来源含地名《XX》，未提取"
   - 如果来源是泛指性文献（如《明史》《明实录》），则跳过不提取
   - 无法推断时跳过不提取

9. **多县以顿号连接**
   - 如：`曲沃、洪洞、临汾...大旱，人相食`
   - 拆分成多条独立记录，每条记录对应一个县
   - 如果这些县同属一个古代府/州，则古代地名字段填相同的古代府/州名

10. **"县等："开头且内容包含多县**
    - 如：`静宁县等：静宁、灵台、肃州等处大旱...`
    - 拆分成多条独立记录，分别对应静宁、灵台、肃州

11. **古代地名处理**
    - 对于古代府级单位如"泽州""解州""绛州""秦州""庆阳""肃州"等
    - 在"古代地名"字段保存原名称
    - 省/市/县字段填现代对应行政区划（如泽州→山西晋城市、肃州→甘肃酒泉市）
    - 仅记录独有古代地名（现代不再使用的名称）；现代仍在使用的地名（如"庆阳""庄浪"）不记为古代地名

12. **特殊地名转换**
    - 如"辽东"→"辽宁"，"秦、晋"→分别转换为陕西、山西
    - "都下"→"北京"
    - 在备注字段注明原文情况

13. **分号分隔符**
    - 个别行使用分号`；`代替冒号`：`（如`平原县；大风折苗`），程序需兼容两种分隔符
    - 分号前为地名，分号后为事件描述

14. **从来源推断地名**
    - 无明确地点开头但来源含地名的记录（如`——万历《渭南县志》`）
    - **不进行推断**，在备注中标注"来源含地名《XX》，未提取"
    - 无法推断时跳过不提取

15. **古代地名映射表**
    - 建立古代州名/府名到现代行政区划的映射表（同时保留原名在"古代地名"字段）
    - **仅记录现代已不用的古代地名**；现代仍在使用的地名（如庆阳、庄浪、辽东等）不记为古代地名

    | 凤台县 | 山西省晋城市 | 清代为凤台县，今晋城市城区 |

16. **志书级别识别**
    - **不进行志书级别的地点推断**，遵从记录本身的地名
    - 如需标注来源级别，在备注中注明即可

17. **OCR错误/原文错误处理**
    - 发现无法辨认的地名时（如"个人信息"），在备注字段标注"疑似OCR错误"
    - 如：`孝义、个人信息大旱` → 个人信息位置填"疑似OCR错误"，备注注明原文
    - 无法确定的古代地名，保留原文本并在备注中说明

18. **泛指性多行政区划记录**
    - 如`两京、山东、河南、湖广、江西...`等多省泛指，跳过不提取
    - 如`淮、扬、庐、凤游饥`等府级泛指，跳过不提取
    - 仅提取有明确县名记载的记录

19. **"X等"格式的歧义处理**
    - `县名等：内容` → "等"指代该县及邻近区域，拆分为一条记录（县名去掉"等"）
    - `府名等：多个县` → "等"指代前面提到的多个具体县，需拆分
    - `淮、扬、庐、凤等府饥` → 泛指，跳过不提取

20. **无记录可提的处理**
    - 如果某段落完全没有符合条件的记录，将该段落原文完整填入备注字段
